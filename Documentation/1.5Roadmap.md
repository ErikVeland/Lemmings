# 1.5 NeoLemmix compatibility roadmap

## Objective

Version 1.5 targets NeoLemmix 12.14 data and replay compatibility plus the
current NeoLemmix Community Edition contract. The source oracle is
[NeoLemmix Community Edition 1.2.0](https://github.com/Willicious/NeoLemmixCommunityEdition)
at commit `38d0449f87501798e78ac668a9494848f4aa9649`.

NeoLemmix content remains Beta or Preview until every release gate below passes.
An imported level or a deterministic smoke run is not a replay or behaviour
compatibility claim.

## Current source boundary

- `.nxlv` parsing retains level, style, terrain, gadget, skill and trait data.
- Style resolution and static rendering support the pinned CE level corpus.
- Generated pickup animations are recognised. Static rendering leaves their
  generated skill icon blank and the simulator rejects pickup gameplay.
- The deterministic simulator implements 19 of the 21 current skills. Fencer
  and Laserer remain explicit unsupported results.
- The current section-based `.nxrp` decoder retains metadata, assignments,
  spawn-interval changes and nuke commands. Selection cross-check fields are
  not yet connected to simulation, and legacy replay files are rejected
  explicitly.
- The corpus runner separates import/render failures from levels that need a
  known unsupported mechanic. `--require-runnable` converts every unsupported
  level into a failing gate.

## Gates

| Gate | Development evidence | 1.5 exit condition |
| --- | --- | --- |
| Recognised | Typed `.nxlv` and current `.nxrp` decoders | Every retained pack and replay has a stable identity and format result |
| Imported | Pinned CE level corpus and optional replay-import corpus | No required field, dependency or command is lost |
| Rendered | Real CE styles, terrain masks, objects and lemming sprite resolution | Reference images and animated object states match the oracle |
| Runnable | Deterministic smoke, save and restore checks for supported levels | Strict corpus mode has no unsupported level or mechanic |
| Replay-compatible | Replay command decoder and deterministic command queue | Real reference replays reproduce completion frame, result and final state |
| Behaviour-compatible | Focused synthetic rule tests | Skills, gadgets, zombies, Superlemming and CE rule changes match the oracle |
| Complete | No claim | Every advertised level has retained winning evidence and recovery checks |

Passing one row does not imply that a later row passed.

## Repeat the gates

Run the data-independent source tests:

```sh
zsh Scripts/check-1.5-neolemmix.sh
```

Run the development level-corpus gate against the pinned CE checkout:

```sh
zsh Scripts/check-1.5-neolemmix.sh \
  --ce-root /path/to/NeoLemmixCommunityEdition \
  --require-ce-corpus
```

Run the strict gate when every current mechanic should be runnable:

```sh
zsh Scripts/check-1.5-neolemmix.sh \
  --ce-root /path/to/NeoLemmixCommunityEdition \
  --require-runnable-corpus
```

Import a supplied replay corpus without claiming result parity:

```sh
zsh Scripts/check-1.5-neolemmix.sh --replays-root /path/to/reference-replays
```

The committed GitHub workflow repeats the data-independent source gate. It does
not download third-party styles or levels. Run the pinned level-corpus gate
locally only with content that you may lawfully use. CI does not close the real
corpus, strict runnable or reference-replay gates.

## Open implementation work

- Implement Fencer and Laserer with canonical terrain masks.
- Implement locked exits and buttons, pickups, teleporters and receivers,
  updrafts, splat pads, splitters, force fields and portals.
- Implement zombie infection, neutral and skill-state changers, and
  Superlemming.
- Match exact destructive masks, Slider transitions, multi-entrance ordering,
  gadget occupancy, paired state and animation timing.
- Pair real `.nxrp` files with their exact levels and run them to the declared
  completion frame twice. Compare result and final state with the source engine.
- Retain and validate replay selection identity, position, direction and
  spawned-lemming cross-check fields before native playback is enabled.
- Verify pack progress, save recovery, replay identity and changed-content
  rejection in the player-facing application.

## External evidence needed

The reviewed CE 1.2.0 checkout contains levels and styles but no reference
`.nxrp` files. Its bundled graphics have separate use restrictions. Full
closure therefore needs lawfully held level, style and replay corpora that
cover every required mechanic and pack. Record the source URL or owner,
version, commit or archive hash, level identity, replay hash, result and licence
status. Do not commit third-party game data unless redistribution is authorised.
