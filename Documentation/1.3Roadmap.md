# 1.3 iPhone and iPad roadmap

Updated 25 September 2026. This roadmap defines the first mobile source
milestone. It does not make an App Store or device-release claim.

## Decision

Version 1.3 adds an iPhone and iPad application target without changing the
macOS 1.2 product version. The first player-facing mobile slice is Classic DOS
content imported from a folder that the player owns. Commercial game data is
not part of the application bundle.

Lemmings 2 and Lemmings 3 use the same mobile session, targeting, lifecycle and
checkpoint boundaries. Their adapters have synthetic checkpoint tests. Their
mobile data import and native renderers are not player-facing 1.3 content, so
the iOS app must not present either sequel as available.

## Source scope

| Area | 1.3 exit condition | Current source state |
| --- | --- | --- |
| Application target | A real UIKit target supports iPhone and iPad on iOS 16 or later. | Implemented in `Apps/UltimateLemmingsIOS`. Version 1.3, build 1. |
| Shared runtime | Mobile code uses typed engine contracts and does not place gameplay rules in view controllers. | `LemmingsMobileCore` owns geometry, targeting, lifecycle, performance, checkpoints and engine sessions. |
| Rendering | The playfield uses Metal and preserves nearest-neighbour pixel artwork. | Implemented with an `MTKView`, a platform-neutral pixel frame and an anchored viewport. |
| Touch | Direct selection is precise in crowds. Dragging does not assign a skill. Pinch keeps its level-space anchor. | Implemented with stable eligible-first targeting, follower and tool-holder preferences, a touch state machine, pan and zoom. |
| Layout | Controls remain in the safe area and have at least 44-point input targets in portrait and landscape. | Implemented and covered for representative iPhone and iPad layouts. |
| Recovery | Inactive, background and audio-interruption paths pause, cancel input and save once. Returning requires an explicit Resume action. | Implemented with versioned, checksummed, atomic primary and backup checkpoints. |
| Performance | Display work can reduce under thermal, low-power and accessibility pressure without changing simulation rules. | Implemented with fixed simulation ticks and presentation-only budgets. |
| Content import | A selected folder is staged, bounded, checked for symbolic links, parsed, then committed with rollback. | Implemented for player-owned Classic DOS data. |
| Accessibility | Controls have names, state and direct-interaction hints. The UI does not rely on colour alone. | Source implementation is present. A complete VoiceOver listening journey remains a device gate. |
| Automation | Core tests, Simulator builds, an unsigned device build and iPhone/iPad launch-and-rotation checks run in CI. | The workflow is in `.github/workflows/ios-1.3.yml`. A CI result is evidence only for the commit that ran. |

## Source verification

Run the data-independent gate from the repository root:

```sh
zsh Scripts/check-1.3-mobile.sh --require-sdk
```

The gate parses every mobile source file, validates the project and privacy
metadata, runs the focused core tests, builds the Debug and optimised Release
products with the iOS Simulator SDK, and builds an unsigned arm64 Release
product with the device SDK. `--require-sdk` also requires an installed iOS
Simulator runtime because Xcode needs one to compile the asset catalogue.

The focused tests cover:

- iPhone and iPad safe-area layouts and minimum input sizes;
- anchored zoom, pan bounds and tap-versus-drag routing;
- eligible-first, approaching-follower and tool-holder targeting;
- inactive, background, audio and explicit-resume state changes;
- fixed ticks and presentation-only thermal budgets;
- corrupt-primary recovery and stale-writer rejection;
- staged data import, rollback and symbolic-link rejection; and
- exact Classic, Lemmings 2 and Lemmings 3 checkpoint restoration; and
- Classic jump movement through the optimised shared runtime.

## External acceptance gates

The source milestone does not close the release gate. Before an iOS release:

1. Run the launch and rotation test on current iPhone and iPad Simulator
   runtimes.
2. Complete gameplay journeys on a minimum supported iPhone and iPad and one
   current device of each class.
3. Verify precise crowded selection, pan and pinch with physical touch input.
4. Verify phone calls, headphones, route loss, Control Centre, backgrounding,
   termination and checkpoint recovery on devices.
5. Measure frame time, memory, audio, battery and thermal behaviour during long
   play, fast-forward and mass end-run effects.
6. Complete VoiceOver, reduced-motion, reduced-flash, Dynamic Type and external
   controller journeys.
7. Build with the distribution profile, validate privacy metadata and the app
   icon, then complete TestFlight and App Store checks under approved publishing
   scope.

Record these results against an exact commit and device/OS matrix. A source
build, a Mac test or a successful Simulator launch does not replace them.
