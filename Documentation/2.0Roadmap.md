# 2.0 iOS release roadmap

Updated 12 October 2026. The owner confirmed a full iOS release for iPad,
iPhone and iPhone Duo, with Classic, Lemmings 2 and Lemmings 3 at launch.
Version 1.3 build 1 is the recorded development source milestone. The current
iOS target uses version 2.0 metadata. The full three-game release is not ready
for TestFlight or the App Store.

## Decision

Adaptive presentation is a core release requirement across all three games.
Device capabilities choose the initial budget; measured CPU/GPU work and system
pressure determine sustainable effect quality. Preserve sharp artwork, gameplay
rules, input and accessibility limits. Mac and iOS share the policy. Physical
device acceptance and a future Apple TV adapter remain separate gates. See
[adaptive presentation](AdaptivePresentation.md).

Version 2.0 must make all three native games available through one iOS library.
The existing Classic-only prototype is the starting point, not the launch scope.
Reuse the current simulation rules, original artwork and preserved replay
fixtures. Keep game-completion claims separate from mobile release acceptance.
L2 is Complete and L3 is Beta under the current Mac release scope. The native
route gate now records 120/120 L2 routes and 90/90 L3 routes; each L3 tribe's
30-level chain also finishes with 50 survivors. These results do not establish
original-engine parity or mobile playability. See [campaign evidence](CampaignCompletion/README.md)
and [release scope](ReleaseScope.md).

The prototype imports player-owned Classic DOS data. The first device-beta
workflow also bundles the 120-level Classic campaign for offline startup.
Normal Xcode Debug builds include the local approved Classic inputs when
available. Source-only builds without those inputs retain the import path.
See [device beta preparation](ReleaseReadiness/2.0DeviceBeta.md).

The iPhone Duo experience is part of the 2.0 launch scope. The app must adapt
one live game session across the closed outer display, the open inner display,
and supported partially folded poses. It must also remain usable when iOS
resizes the app for multitasking. Duo support is a release gate, not a later
enhancement.

Build and validate the release with Xcode 27 and the iOS 27 SDK. The minimum
supported OS version is a separate release decision. The current project still
sets iOS 16.0 as its deployment target; this is not yet a 2.0 support decision.

Lemmings 2 and Lemmings 3 use the same mobile session, targeting, lifecycle and
checkpoint boundaries. Their adapters have synthetic checkpoint tests. Their
mobile content loading, native renderers and campaign flows are required for
2.0. Keep unavailable entries honest during development. Do not expose either
sequel as playable until its data, frame output, input and recovery paths work.

## Delivery sequence

Each slice must work across all three games before its release gate closes.
Reuse shared controls and flows. Keep engine-specific limits in the evidence.

1. **Shared library and content.** The shell now uses engine-independent
   library, level-summary and session-content contracts. Add per-game saved-run
   identities and staged
   L2/L3 content validation, tribe selection and real-data session factories.
   Keep imports for different games independent. Reject changed content during
   recovery without replacing the valid installed copy.
2. **Native sequel rendering.** Move reusable indexed-image composition and
   native animation mappings behind platform-neutral renderers. Use the Mac
   reference canvas and source assets for terrain edits, object ordering,
   directional sprites, tools, prisoners, creatures and effects. Preserve each
   engine's pixel aspect and original panels. Verify source-matched frames and
   every input target before exposing the games in the library.
3. **Campaigns and recovery.** Add durable per-game progress and saved runs.
   Preserve L2 survivors and L3 reserves and extras across Continue, Retry,
   termination and relaunch. Distinguish a level win from a tribe ending.
   Never advance across tribes by incrementing a global level index.
4. **Shared play features.** Connect hints, rewind/step, precision targeting,
   settings, controller input and Hot Seat. Restore the full roster and turn
   ownership with a saved run. Keep handovers paused until the next player is
   ready. Follow the current engine support limits for hints and transport.
5. **Audio and media.** Connect music, effects, L3 voices and supported original
   media. Recover from interruptions and route changes only after explicit
   Resume. Keep mechanical tests silent without changing saved preferences.
6. **Adaptive iPad, iPhone and Duo UI.** Verify portrait, landscape, resized and
   folded layouts for library, briefing, active play, pause, hints, settings,
   results, handover and saved-run selection. Use shipped bitmap controls and
   fonts. Preserve one session while the display configuration changes.
7. **Release candidate.** Run the current source, render, input, recovery,
   campaign, accessibility and device gates. Then freeze source and content,
   set 2.0 version/build metadata, sign the archive, validate TestFlight and
   prepare the App Store submission and device-specific screenshots.

The [gate register](ReleaseReadiness/gates.json) tracks the shared iOS source
baseline, three-game delivery, QoL and Hot Seat, Duo, device acceptance and
mobile distribution separately. Passing the old 1.3 gate cannot close them.

12 October source work adds the Mac-style iPad cover browser in both orientations,
shared HUD rendering and system reserved-region adaptation. Opening a display
keeps the current zoom and run. Horizontal divisions separate level and console.
Menus gain a brief native pixel walker on unfold. Small layouts pause until the

compile pass. Physical Duo, native UIKit acceptance, one-thumb edge controls and
full cross-game parity remain open. See

## iPhone Duo experience

Treat each display pose as a different view of the same rescue. Keep the
simulation, selected skill, camera position and recovery state when the device
opens, closes, rotates or changes size.

- **Closed — Pocket Rescue:** use the compact-width display for one-handed
  play. Keep primary controls within one-thumb reach along the vertical screen
  edge. Show a useful level view without stretching the pixel artwork, and let
  players pan across long levels.
- **Open — The Great Unfold:** use the wider display to reveal more of the
  existing level at its native pixel shape. Keep the level continuous across
  the display, place controls along the outer edge, and keep fixed interactive
  controls clear of the centre hinge and camera regions.
- **Partially folded — Diorama:** when iOS provides a tabletop pose, place the
  live level in the upper region and the relevant play controls in the lower
  region. Keep the same run active as the layout changes.
- **Resized play:** support rotation, iOS Split View and stacked picture-in-
  picture layouts. Reflow controls and the playfield viewport to the available
  safe area.
  Preserve the run if the available area cannot support active play.
- **Unfold moment:** use the shipped pixel artwork for a brief transition in
  menus or level entry. A lemming can step from the closed view into the wider
  landscape. Do not delay or interrupt an active rescue with this animation.

Use iOS size classes, safe areas and system-reported reserved regions to select
these layouts. The installed iOS 27.2 SDK declares the UIKit reserved-region
APIs from iOS 27.1. Keep these calls availability-gated so the existing iOS 16
deployment baseline remains valid. Query division and occlusion regions in the
view coordinate space. Do not infer a fold or camera region from device names
or fixed dimensions. Follow Apple's [iPhone Duo design guidance](https://developer.apple.com/design/human-interface-guidelines/designing-for-iphone-duo)
and [adaptive layout guidance](https://developer.apple.com/videos/play/tech-talks/111463/).
Do not depend on fixed screen dimensions. The hinge may cross the live
playfield, but it must not hide fixed controls or prevent precise lemming
selection. Preserve nearest-neighbour rendering and the game's bitmap
interface rules in every pose.

## Source verification

Run the existing data-independent baseline gate from the repository root:

```sh
zsh Scripts/check-1.3-mobile.sh --require-sdk
```

The gate parses every mobile source file, validates the project and privacy
metadata, runs the focused core tests, builds the Debug and optimised Release
products with the iOS Simulator SDK, and builds an unsigned arm64 Release
product with the device SDK. `--require-sdk` also requires an installed iOS
Simulator runtime because Xcode needs one to compile the asset catalogue.

The focused tests cover:

- iPhone and iPad safe-area layouts and minimum input sizes;
- closed, open and iPad aspect-ratio layout selection, including right-to-left rails;
- anchored zoom, pan bounds and tap-versus-drag routing;
- camera-centre preservation and restored-origin handling when views resize;
- eligible-first, approaching-follower and tool-holder targeting;
- inactive, background, audio and explicit-resume state changes;
- fixed ticks and presentation-only thermal budgets;
- corrupt-primary recovery and stale-writer rejection;
- staged data import, rollback and symbolic-link rejection;
- exact Classic, Lemmings 2 and Lemmings 3 checkpoint restoration; and
- Classic jump movement through the optimised shared runtime.
