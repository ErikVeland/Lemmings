# 2.0 device beta

This procedure prepares a Classic device beta. The 2.0 launch still requires
Classic, Lemmings 2 and Lemmings 3 on iPhone, iPad and iPhone Duo.
L2 and L3 mobile libraries, renderers and campaign flows remain open.

## Build an installable candidate

Use the stable Xcode installation and team `54WU29TRTY`. The installed Apple
Development certificate belongs to this team. The iOS bundle ID is
`academy.glasscode.lemmings.ios`. Override these values only for a different
publishing account or app record.

```sh
python3 Tools/IOSBeta/build.py --build 1 \
  --export debugging --allow-provisioning-updates
```

Normal Xcode Debug runs automatically bundle the approved Classic data from
`Sources/Ports/lemmings_dos_1991-07-30` when that local folder exists. This avoids
replacing a playable beta with an import-only build. A staged
`IOS_BETA_CONTENT_DIR` overrides local development data. Release builds still
require that explicit staged path. For import-only Debug builds, set
`IOS_LOCAL_CLASSIC_DATA_DIR` to an empty value. No original executable is bundled.
See [iPad campaign recovery](2.0DeviceBeta-2026-10-11/Build4/DataRecovery/README.md).

Use a new build number after every uploaded build. Choose a new output directory
if a previous local attempt already created the default candidate directory.
The script refuses to replace an existing candidate.

For the connected GenErik iPad, use its UDID to register the device and verify
that the exported profile includes it:

```sh
python3 Tools/IOSBeta/build.py --build 3 \
  --output .build/ios-beta/2.0-3-ipad --export debugging \
  --allow-provisioning-updates --device-id DEVICE_UDID
```

Unlock the iPad and accept the Mac's trust request before this command.
Both GenErik devices use the same name. Select the iPad by UDID, not by name.

If Apple Developer already lists the iPad but Xcode cannot use it as a run
destination, use `--registered-device-id DEVICE_UDID` instead of `--device-id`.
The helper archives for generic iOS and still rejects an export whose profile
excludes the requested device. This option does not register a missing device.

The script stages 26 original Classic data files from
`Sources/Ports/lemmings_dos_1991-07-30`. It excludes original executables,
documents, settings, music and other game assets. Commercial inputs remain
inside ignored `.build` output. The app reads bundled data without an import
or network connection. A player-imported Classic folder takes precedence.

The script renders every level and verifies checkpoint restoration before
archiving. It verifies the compiled icon, privacy declarations, version,
device architecture, content hashes and matching crash symbols. It records
source hashes before and after the build. A changed source invalidates the
candidate. It exports an IPA but does not upload, install or launch it.

Outputs include the archive, dSYMs, IPA, logs, content validation,
source manifest and `evidence.json`. Keep these together for crash diagnosis.
The exported app is extracted to `Install/Payload`. Its signature, content,
metadata, crash-symbol UUIDs and requested-device profile membership are checked.

For source preparation without signing:

```sh
python3 Tools/IOSBeta/build.py --build 2 --unsigned
```

An unsigned archive cannot be installed or sent to TestFlight.

## Install on a registered device

For a development export, enable Developer Mode on the device. Pair and trust
the Mac. Unlock the device before installation. The provisioning profile must
include its UDID. Xcode must have access to the development signing key.

The install helper checks the retained IPA, executable, crash-symbol identity,
content, signature, profile expiry, developer team and exact device membership.
It refuses candidates that failed final source verification, even if an IPA
was exported. It installs without launching the app and verifies the installed
version/build:

```sh
python3 Tools/IOSBeta/install.py .build/ios-beta/2.0-3 \
  --device-id DEVICE_UDID
```

Use the retained candidate directory if it differs from this example. The helper
never selects a device by its name. Each attempt creates a separate delivery
record and logs inside the candidate directory. An install exit code alone does
not establish the installed build.

If CoreDevice cannot reach a trusted USB device, the already-installed iMazing
CLI can use its alternate device connection. Select it with `--backend imazing`.
The CLI requires a separate activated CLI licence. The installed GUI can use
Manage Apps → action menu → Install .IPA File without the CLI. The same
candidate preflight still applies. Review the device app-info response to
confirm the installed build. This path never claims automatic device acceptance.

Open the installed app on the device when you are ready to test. A completed or
retired run rejects delayed saves. Cleanup of an old run preserves a new retry's
checkpoint across all three engine identities.

## Prepare TestFlight

Create or select the App Store Connect record with the same bundle ID.
Use a stable Xcode version accepted by App Store Connect. Export with:

```sh
python3 Tools/IOSBeta/build.py --build 3 \
  --export app-store-connect --allow-provisioning-updates
```

This exports locally. Upload the reviewed IPA with Transporter or distribute
the archive through Xcode. Start with an internal tester group. Keep automatic
distribution disabled until the candidate passes device checks.
The build helper puts Apple system tools first in its subprocess PATH. This
avoids a Homebrew rsync conflict during App Store symbol copying and does not
change the user's shell configuration.

The export preserves version and build numbers. It does not restrict the
binary to internal testing, so the same candidate can later enter external
beta review. External testing needs Apple's beta review and completed beta
metadata. Supply a feedback email and the review contact before that step.

Suggested beta description:

> Ultimate Lemmings 2.0 device beta. This first mobile candidate includes the
> original 120-level Classic campaign. Test touch controls, rotation, zoom,
> pause, retry and saved-run recovery on iPhone and iPad. Lemmings 2 and 3 will
> join later builds before the full 2.0 release.

Suggested What to Test:

> Start Fun 1 without importing data. Assign skills by touch, then test pan,
> pinch zoom and rotation. Background the app, return and explicitly resume.
> Close and reopen it, then restore your saved run. Check loss/retry and
> win/continue. Report the build, device, OS, level and steps for each problem.

The current mobile slice does not play music or sound effects. Its audio
session and interruption handling exist, but audible playback is not a
completed beta feature. Game Center, Hot Seat and full campaign progress are
also outside this first slice. Do not advertise them in beta metadata.

## Device acceptance

### Touch planning

Select a skill to pause the simulation. Tap a target to assign it, or hold to
inspect the magnified bitmap before releasing. Assignments do not resume time.
Pan and pinch remain available while planning. STEP advances one simulation
tick. The Play symbol resumes. MENU opens the separate paused menu.

Ready screens, menus, backgrounding, interruptions and results block assignments.
Returning from an interruption still requires explicit resume. These controls
are shared across the three mobile session adapters. L2/L3 fixture tests verify
paused assignment and checkpoint replay, but their real mobile rendering and
campaign libraries remain open.

On the iPad, verify these states in portrait, landscape and Split View:

1. Start a level and select a skill. The timer and actors stop.
2. Hold a target. The loupe stays clear of the finger and uses sharp pixels.
3. Release to assign. The skill count changes, but the timer stays stopped.
4. Assign another target, then pan and pinch. Camera gestures spend no skill.
5. Tap STEP. Exactly one simulation tick advances and play stays paused.
6. Tap Play. Time resumes without catching up for the paused interval.
7. Open MENU and background the app. Each screen blocks playfield input.
8. Return and explicitly resume. No held touch commits after interruption.
9. Rotate and resize. All controls remain at least 44 points and reachable.
10. Reopen a saved run. Its Ready screen blocks assignment until START.

Record screenshots and touch results during this manual check. The existing
offscreen native test runner supports AppKit, not UIKit, so actual iPad renders
and UIKit hit testing remain unverified until device acceptance.

Record the installed build, device model, OS and content manifest hash.
Complete the following checks on an iPhone and an iPad. Repeat the adaptive
layout checks on Duo when the hardware is available.

| Check | Pass condition |
| --- | --- |
| Fresh offline launch | Classic shows 120 levels without a Files import. |
| Touch and rotation | Buttons remain reachable. Skill assignment, pan and pinch work in both orientations. |
| Gameplay | Hatch, actors, terrain, skills and result counts render correctly. |
| Pause and interruption | Backgrounding or interruption pauses play. Returning waits for explicit resume. |
| Termination and recovery | Reopening restores the saved level and exact run state, paused. |
| Retry and continue | Loss retries the same level. A win continues to the next authored level. |
| Files import | A valid Classic folder loads. An invalid folder leaves the previous data intact. |
| Update | Installing the next beta preserves imports and valid saved runs. |
| Accessibility | VoiceOver identifies controls and activates them. Touch targets remain usable. |
| Sustained play | Record frame pacing, memory, battery and temperature during a 20-minute session. |

Automated mechanical checks stay headless and muted. Native UI checks must
use `Tools/UITestRunner/run.py` in its default offscreen mode. That runner
does not currently provide a verified iOS workflow. Do not substitute a
foreground Simulator run. Device acceptance remains a manual beta activity.

## Privacy and distribution inputs

The current shared services can transfer linked user and device identifiers and
gameplay content for app functionality. The privacy manifest declares those three
categories, with no tracking, advertising purposes or tracking domains. Archive
validation checks the exact reviewed manifest and rejects changes to that scope.
Signed capability checks decode the embedded DER entitlements with Apple's
`derq`, then require the matching Game Center and shared iCloud Documents profile.

The manifest also declares elapsed in-app
timers (`35F9.1`) and app-owned/user-selected file metadata (`C617.1`, `3B52.1`).
The mobile dependency path uses CryptoKit SHA-256 for content integrity, with
no app-defined encryption. `ITSAppUsesNonExemptEncryption` is false.
Repeat this audit if services, SDKs, collected data or encryption change.
