# 1.7.7 slim download restoration

The slim fresh-install download is required. It was omitted from 1.7.3 after
notarytool could not read its Keychain credential. That temporary exception was
incorrectly carried into the 1.7.6 and 1.7.7 releases.

## Prepared package

The replacement slim archive uses the published 1.7.7 build 61 executable and
resources. All 13,679 files outside Music matched before signing. Only the
music set changed: 54 essential versions remain, and 18 optional libraries
remain available through the same catalogue. The app was signed again with
Developer ID and passed deep, strict signature verification.

The signed submission is about 159 MB. It has not been notarised or published.
Apple's tool cannot currently read the existing `lemmings-beta` profile through
either the default search or the explicit login keychain. Stable Xcode reports
the same error. No password was extracted, and no unnotarised ZIP was uploaded.
See [package status](1.7.7-build61/slim-status.json).

## Verification

- All 34 release-tool tests passed, including rejection of an omitted or missing
  slim archive. The publisher now requires `DOWNLOAD_ZIP` for every release.
- The music-library installer and slim-packaging tests passed. The main set and
  optional libraries cover all 495 versions exactly once.
- All 18 local library archives and their member files passed hash checks.
- All 18 public library assets match their catalogue sizes and SHA-256 hashes.
  Each public URL returned ZIP data. See [live checks](1.7.7-build61/slim-live-libraries.json).
- Offscreen, muted music UI tests passed the first-launch checklist, installed
  recognition, selection, skip persistence, progress, retry and Settings reopen.
  The rendered [soundtrack prompt](1.7.7-build61/slim-library-welcome.png) was reviewed.

## Distribution contract

The slim archive is the recommended fresh-install download. Previously downloaded
libraries remain in Application Support and are detected by the download manager.
The current Sparkle update still carries the full soundtrack because some older
apps store optional music inside their bundles. A future slim update needs to
preserve those files before Sparkle replaces the old app.

Publish the slim archive only after Apple accepts it, the ticket is stapled,
a fresh quarantined extraction passes Gatekeeper and its public checksum matches.
Keep the existing full archive and v1.7.7 source tag unchanged. Update the public
download recommendation after the slim asset is available.
