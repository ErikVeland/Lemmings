## Tahoe-compatible build

The build uses the installed Xcode and SDK. A small adapter resolves Apple's
public Objective-C region classes and selectors at runtime. It checks method
signatures before calling them. Systems without these APIs return no regions.
Inactive folds remain detectable even when their frame is empty. Headless tests
cover these boundaries with Objective-C fakes.

The adapter follows Apple's [region API](https://developer.apple.com/documentation/uikit/uiviewreservedregion)
and [query method](https://developer.apple.com/documentation/uikit/uiview/reservedregionsofkind:options:).
Duo navigation rails use the runtime trait and measured safe-area edges. Header
clearance uses the existing SDK's corner-aware safe area. The newer bar-specific
corner adjustment is not used. Actual Duo event delivery and corner geometry
still need a system check.

## Open release gates

1. Verify the public runtime adapter on a Duo system. The owner requested a
   Tahoe-compatible build, so Xcode 27.2 is not a release prerequisite.
2. Validate both embedded extensions in the signed candidate. Verify Intel
   compilation, Mac loading on macOS 12.3 and complete container signatures.
3. Check calendar access, denial and revocation in the app and both extensions.
   Confirm that permission granted to the host is available to its extension.
4. Inspect the actual widget gallery, Lock Screen and StandBy renders.
   Bitmap family captures do not replace these system checks.
5. Exercise clock dismissal, sleep/wake, charging, idle entry, pose changes and
   input isolation on supported devices. Keep gameplay and Ready handovers paused.
6. Check the new settings and ghost visibility during Classic, L2 and L3 play.
   Verify physical touch, controller input and VoiceOver.
7. Assign candidate versions and build numbers after checking existing deliveries.
   Complete signed archives, symbols, upgrades, processing and TestFlight availability.
