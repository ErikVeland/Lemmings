## Signing-host hand-off

After human review, merge the PR and check out the approved commit on the
signing Mac. Restore the required player-owned assets and confirm the proposed
mobile build numbers in App Store Connect. Configure the Developer ID identity
and notary credentials as described in the [release packaging guide](../../README.md#local-release-packaging).
Run the existing package script from a clean checkout:

```sh
RELEASE_BASE=v2.1.2 RELEASE_TAG=v2.2 zsh Scripts/build-and-notarise.sh --dry-run
RELEASE_BASE=v2.1.2 RELEASE_TAG=v2.2 zsh Scripts/build-and-notarise.sh
```

The script prints the frozen commit, signed update ZIP, slim download ZIP,
appcast and stamped notes paths. Record these values. Follow the
[Sparkle publication procedure](../AutomaticUpdates.md#release-procedure):
set `RELEASE_TAG=v2.2`, `RELEASE_VERSION=2.2`, `RELEASE_COMMIT`,
`RELEASE_NOTES_PATH` and `DOWNLOAD_ZIP` to the printed values. Run
`Scripts/publish-github-release.sh --check` with the update ZIP path. After
package, hardware, update and human approval checks pass, run the same command
without `--check` and with `RELEASE_APPROVED=1` to publish the GitHub release
and Sparkle feed. Upload signed iOS and tvOS archives through the separate
TestFlight distribution process; record tester availability after processing.
