## Launch polish

The 23 October source pass is based on release-preparation commit `240c68b2`.
It addresses three reproduced problems:

- Narrow pause and confirmation menus split button words at large text sizes.
  The shared footer now honours one-column layouts. Back sits above the primary
  forward action when two readable columns cannot fit. The pause audit now
  rejects split words instead of recording a warning.
- A calendar read could complete after the clock closed, became inactive or
  lost permission. An injected reader cancels obsolete deliveries and checks
  permission again. The clock clears both its rendered event and accessibility
  text when it closes or the app becomes inactive.
  Duplicate settings handlers no longer hide the calendar-permission recovery
  route. With calendar access denied, the events row opens
  iOS Settings and keeps the saved choice.
- Four bundled fan records have impossible rescue conditions. The shared
  [exclusion manifest](../../Resources/Progression/bundled-playable-exclusions.json)
  now applies to Mac, iOS and TV browsing, counts and shuffle. Each exclusion
  requires the exact bundled folder, archive name, SHA-256 and member. Source
  archives and imported copies stay intact. Remaining saved level keys stay
  intact. Pack resume resolves the saved identity after menu indexes shift.
  Playable scope becomes 6,016 levels, with 2,404 verified routes and
  3,612 routes still open. Exclusion adds no winning route.

The [structural evidence](ClassicFanStructuralBlockers-2026-10-20.json) records
the four impossible rescue conditions. Their archive hashes match the installed
2.1.1 resources used by the local integration check. This does not certify a
signed 2.2 package.

## Desk Clock port

The 23 October port adds the reviewed Desk Clock repair from
`feature/desk-clock` at `9df0b6cf`. It keeps the launch polish, the release
preparation and the controller from this branch. The branch had one clock
screen. `MobileDeskClock.swift` held only the touch observer, which moves into
the new automatic entry.

- Only an idle Duo Home opens the clock by itself. VoiceOver, an active text
  field, a sheet, a loading level, a moving list and every game screen block
  it. A paused Hot Seat turn counts as a handover.
- A shown automatic clock closes when its pose or power no longer holds. A
  touch on the clock no longer closes it. A clock that the player opened
  stays until the player closes it.
- The "Show next event" row opens iOS Settings whenever calendar access is
  denied. Before, the first tap changed the saved choice with no visible
  change. The unused calendar handler is removed.
- The artwork prune tool refuses unsafe destinations and fails at 2 MB.
  The iOS Info.plist has one pair of calendar usage keys.
- New tests cover the trigger wiring, calendar access mapping, the events
  row, Close under VoiceOver in every pose, pruned frame coverage and the
  widget renders.

## Signing-host hand-off

After human review, merge the PR and check out the approved commit on the
signing Mac. Restore the required player-owned assets and confirm the proposed
mobile build numbers in App Store Connect. Configure the Developer ID identity
and notary credentials as described in the [release packaging guide](../../README.md#local-release-packaging).
Run the existing package script from a clean checkout:

```sh
RELEASE_BASE=v2.1.2 RELEASE_TAG=v2.2 zsh Scripts/build-and-notarise.sh --dry-run
RELEASE_BASE=v2.1.2 RELEASE_TAG=v2.2 zsh Scripts/build-and-notarise.sh
```

The script prints the frozen commit, signed update ZIP, slim download ZIP,
appcast and stamped notes paths. Record these values. Follow the
[Sparkle publication procedure](../AutomaticUpdates.md#release-procedure):
set `RELEASE_TAG=v2.2`, `RELEASE_VERSION=2.2`, `RELEASE_COMMIT`,
`RELEASE_NOTES_PATH` and `DOWNLOAD_ZIP` to the printed values. Run
`Scripts/publish-github-release.sh --check` with the update ZIP path. After
package, hardware, update and human approval checks pass, run the same command
without `--check` and with `RELEASE_APPROVED=1` to publish the GitHub release
and Sparkle feed. Upload signed iOS and tvOS archives through the separate
TestFlight distribution process; record tester availability after processing.
