# Duo front display and tent clock correction

Date: 23 October 2026, Australia/Brisbane.
Status: Signed local build 32 is installed on the Duo. The owner confirmed automatic Desk Clock entry in Tent Pose, red-only night vision there, and no lemmings stuck in a digit through a minute change on build 31. The build 32 ground and spacing correction has passed local render checks; physical layout and wider play remain to be checked.

The owner reported an unused strip on the front display, a clock that did not
fill its screen, no automatic clock entry from gameplay in tent pose, and a
crash immediately when opening Desk Clock from the Home menu button.
The connected Duo reported Ultimate Lemmings 2.2.1, build 21 at the time of
the crash. The owner confirmed that the Home-button clock stayed open after
the source fix, but automatic Tent Pose entry still failed in build 25.
Build 26 stayed on the menu in Tent Pose. UIKit reported the physical hinge as
`closed` at 0.905 radians (about 52 degrees) on the active outer display. Build
28 uses that measured state and was captured opening the clock across the full
front display. Build 29 corrected night brightness. Build 30 corrects clock-world
collision and screen placement and adds optional red-only night vision. Build 31
observes the active window's hinge as well as the library view, keeps the last
measured hinge through display-handoff updates without hinge data, and prevents
a builder from choosing a work position inside its own next block. Build 32
replaces the short repeating rock fill with a wider seamless strip of Macintosh
artwork, lowers the ground and exit toward the camera-safe boundary, and adds
space between the next-event lines.

## Changes

- Use full outer-display bounds for Home, level browsing, Ready, gameplay,
  pause, results, recovery and settings. Clear headings, rows, status and input
  targets around local camera cutouts without reserving an entire edge.
  Divided inner-display layouts keep their pane geometry.
- Draw the clock across the full display. Reflow terrain digits, event text,
  stars, grass and ground. Keep important content inside a separate safe
  rectangle and Close inside its existing safe target. Keep widget rendering.
- Observe the public `UIHingeInteraction` on the library's scene content view,
  which stays in the hierarchy while a level or sheet covers it. A partially
  open hinge with an undivided front display triggers tent entry in either
  orientation, without idle, charging or
  screen restrictions. This is a combined hinge/region inference, not a system
  property named tent pose.
- Pause the live attempt and any presented replay, suspend audio and frame
  advancement, block input and preserve the current menu or Ready boundary.
  Closing the clock requires explicit Resume or Ready. The shared controller
  covers Classic, Lemmings 2 and Lemmings 3.
- Let an explicit dismissal suppress tent entry until the phone leaves the
  pose. Automatic exit permits immediate re-entry. Other idle Home triggers
  retain their settings and 60-second delay. A known open hinge no longer
  counts as closed merely because its division is inactive.
- Recognise the Duo's measured 0.905-radian Tent Pose even when UIKit reports
  `closed`; a shut hinge below 30 degrees still does not trigger Tent Pose.
- Keep walkers on digit terrain until a visible exit or explosion, and finish
  active workers as walkers after a time jump. Project falls continuously from
  the enlarged digits to the full-width ground.
- Remove the live clock's extra 60% black overlay after 22:00. System display
  brightness controls the clock's brightness.
- Keep the Lemmings 2 and 3 Home buttons the same width when a corner cutout
  shortens one button, with their bitmap drawing and touch targets aligned.
- Register the clock before editing or gameplay suspension can provoke another
  layout check. Cap full-screen animation bitmaps at three million pixels and
  reuse the rock tile image across frames.
- Present a window-backed clock through UIKit with `.overFullScreen` from the
  top visible controller. The installed build made the clock a child of the
  library, then inserted its view directly into the window. UIKit aborted on
  that hierarchy check before drawing the clock. Detached layout fixtures
  continue to use matching child containment in the host view.

The 21:05:15 Duo report for installed 2.2.1 (21), incident
`C4BB2458-2D8C-43DC-80A5-96B5883EA7A1`, shows `SIGABRT` on the main thread
in `UIView(Hierarchy) _associatedViewControllerForwardsAppearanceCallbacks`
during `MobileDeskClockController.present(in:)`. This rules out calendar access
and first-frame artwork as the immediate crash cause. The owner verified that
the Home-button clock stays open after the fix. A window-backed UIKit regression test exercises the
presentation path, but it has only been type-checked in this environment.

The first focused test invocation could not write the global Clang cache.
Workspace-local module caches resolved this. The first UIKit test source check
lacked Swift Testing's macro plugin path. Adding the installed plugin path
resolved it. The first ground-edge assertion sampled the sky row in the flipped
bitmap. Sampling the actual ground row resolved the assertion; visual inspection
confirmed both edges.

Local logs, modules and renders remain in ignored `.build/duo-front-tent-*`
paths. The tests use an isolated package containing the checkout's sources,
without Sparkle or unrelated test targets. Artwork/data came from the local
export and installed Mac app. This is not signed-candidate resource validation.
The later crash and packaging checks are in `.build/duo-clock-crash-*`.
