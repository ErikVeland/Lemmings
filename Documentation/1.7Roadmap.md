# 1.7 NeoLemmix compatibility roadmap

## Objective

Version 1.7 targets NeoLemmix 12.14 data and replay compatibility plus the
current NeoLemmix Community Edition contract. The source oracle is
[NeoLemmix Community Edition 1.2.0](https://github.com/Willicious/NeoLemmixCommunityEdition)
at commit `38d0449f87501798e78ac668a9494848f4aa9649`.

NeoLemmix content remains Beta or Preview until every release gate below passes.
An imported level or a deterministic smoke run is not a replay or behaviour
compatibility claim.

The [1.7 preparation record](ReleaseReadiness/1.7NeoLemmixPreparation.md)
lists the current inputs and first work slices. The earlier
[1.5 source handoff](ReleaseReadiness/1.5NeoLemmixHandoff.md) retains its
historical corpus results.

## Current source boundary

- `.nxlv` parsing retains level, style, terrain, gadget, skill and trait data.
- Style resolution and static rendering support the pinned CE level corpus.
- Paint objects clip to solid terrain in the static renderer.
- Generated pickup animations are recognised. Static rendering leaves their
  generated skill icon blank. The simulator applies one-use pickup counts,
  including the finite-stock cap and zombie exclusion.
- The simulator handles exit buttons and locked exits, including a same-tick
  unlock when the final button is pressed. Their primary animations start on
  CE frame 1, advance on the trigger tick, settle permanently on frame 0 and
  survive recovery in mid-transition. Capture comparison with CE remains open.
- Reusable and one-shot traps expose their live primary-animation frame, advance
  after lemming processing, and become ready on the first tick after their CE
  animation wraps. Mid-animation recovery is deterministic.
- Foreground gadgets in CE's always-animate set advance their retained primary
  frames from the simulation tick. Entrances remain on frame 1 until the hatch
  opens, advance on that tick, and settle on frame 0 after the opening cycle.
  Splitters render frame 0 or 1 from their current alternating output direction.
- The deterministic simulator implements all 21 current skills. Fencer uses a
  derived four-stage rising mask. Laserer uses the CE beam search, hit offsets,
  directional material rules and derived 9-by-9 mask.
- Digger assignment timing, Builder and Platformer collision movement, Jumper
  wall and head probing, Walker-to-Faller transitions, action-specific initial
  fall distances, Swimmer diving, falling Oh-No/Stoner animations and
  Slider/Dehoister wall probes follow the pinned CE routines.
- Teleporters, receivers, updrafts, splitters, force fields, portals, zombie
  infection, neutral changers and permanent-skill changers have focused state,
  timing and save-restoration tests.
- Splat and anti-splat pads apply at the landing point, with anti-splat and
  Floater or Glider protection taking precedence.
- The current section-based `.nxrp` decoder retains metadata, assignments,
  spawn-interval changes, nuke commands and recorded assignment checks.
  Strict native playback compares level identity, lemming identity, position,
  direction, spawned count and the recorded rescue frame. CE-compatible source
  playback selects by identifier or index and retains position and direction as
  repair diagnostics because CE does not reject normal playback when those
  fields drift or when a recorded assignment fails. Both modes apply replay
  actions before the next simulation tick, handle spawn-interval changes first
  and preserve source order, including a clone assigned later in the same
  frame. Legacy replay files are rejected explicitly.
- The corpus runner separates import/render failures from levels that need a
  known unsupported mechanic. `--require-runnable` converts every unsupported
  level into a failing gate.
- The pinned CE 1.2.0 strict corpus passes: 794 levels, 251,064 deterministic
  ticks, 48,552 explicit visual-limit warnings, zero unsupported levels and
  zero import or render failures.
- The native app resolves the level theme's runtime lemming style instead of
  using Classic sprite stand-ins. Corpus validation covers 794 levels, 59
  themes and 15,104 action, direction and state frames. It follows CE's
  Jumper progress buckets and carries declared alternate-shade HSV offsets
  through theme and state recoloring. The player-supplied style pixels remain
  outside the app bundle.
- Native saved-run tests cover NeoLemmix input replay, deterministic
  continuation, encoded state, cross-build state fallback and changed terrain
  rejection. Player-facing pack progression still needs exact-version winning
  routes.
- The native playfield rebuilds its terrain layer from the live simulation on
  every changed tick. Destruction reveals the retained background, construction
  uses CE's twelve-step gradient around the theme `MASK` colour, and foreground
  gadgets remain above both. Per-pixel provenance preserves destroy-then-rebuild
  results across encoded recovery; CE's constructive no-overwrite rule also
  replaces partially transparent terrain while preserving fully opaque art. A
  finished Stoner draws the player-supplied canonical 16-by-11
  `gfx/mask/stoner.png` into the terrain layer at CE's exact foot-relative
  origin. It retains the owning lemming and source pixel, so it neither
  overwrites existing terrain nor appears above foreground gadgets.

## Gates

| Gate | Development evidence | 1.7 exit condition |
| --- | --- | --- |
| Recognised | Typed `.nxlv` and current `.nxrp` decoders | Every retained pack and replay has a stable identity and format result |
| Imported | Pinned CE level corpus and optional replay-import corpus | No required field, dependency or command is lost |
| Rendered | Real CE styles, terrain masks, objects and lemming sprite resolution | Reference images and animated object states match the oracle |
| Runnable | Deterministic smoke, save and restore checks for supported levels | Strict corpus mode has no unsupported level or mechanic |
| Replay-compatible | Decoder and checked synthetic playback | Real reference replays reproduce completion frame, result and final state |
| Behaviour-compatible | Focused synthetic rule tests | Skills, gadgets, zombies and CE rule changes match the oracle |
| Complete | No claim | Every advertised level has retained winning evidence and recovery checks |

Passing one row does not imply that a later row passed.

## Repeat the gates

Run the data-independent source tests. The script retains its 1.5 name because
that is when the source gate was added:

```sh
zsh Scripts/check-1.5-neolemmix.sh
```

Run the development level-corpus gate against the pinned CE checkout:

```sh
zsh Scripts/check-1.5-neolemmix.sh \
  --ce-root /path/to/NeoLemmixCommunityEdition \
  --require-ce-corpus
```

Run the strict gate when every current mechanic should be runnable:

```sh
zsh Scripts/check-1.5-neolemmix.sh \
  --ce-root /path/to/NeoLemmixCommunityEdition \
  --require-runnable-corpus
```

Import a supplied replay corpus without claiming result parity:

```sh
zsh Scripts/check-1.5-neolemmix.sh --replays-root /path/to/reference-replays
```

Run matched older source replays through their levels and require a native win
by the same five-minute tail used by the CE replay checker:

```sh
zsh Scripts/run-nxrp-paired-corpus-diagnostics.sh \
  /path/to/levels /path/to/replays /path/to/styles
```

Require level identity, completion frame and assignment or spawn checks in
every supplied replay:

```sh
zsh Scripts/check-1.5-neolemmix.sh \
  --replays-root /path/to/reference-replays \
  --require-replay-fields
```

This checks recorded fields only. It does not replay the levels or compare
their results with CE.

The committed GitHub workflow repeats the data-independent source gate. It does
not download third-party styles or levels. Run the pinned level-corpus gate
locally only with content that you may lawfully use. CI does not close the real
corpus, strict runnable or reference-replay gates.

## Open implementation work

- Keep the legacy LVL Superlemming marker in the Classic-family path. CE 1.2
  does not parse a Superlemming field in current NXLV levels, so it is not a
  NeoLemmix 12.14 compatibility feature.
- Match pickup icons, moving backgrounds, trigger-controlled secondary
  animations, and paired teleporter/receiver animation with CE. Unconditional
  secondary layers retain their offsets, Z-order, transforms, resize and live
  frame cycle. Trap, button, locked-exit, entrance, always-animate and Splitter
  primary-frame state are implemented. Compare their captured pixels with CE.
- Compare the runtime lemming animation and recolored pixels against CE
  captures. Native sheets, foot anchors, direction, CE Jumper frame selection,
  alternate shades, and athlete, zombie and neutral recoloring are wired and
  corpus-validated.
- Preserve the clean March 2025 Lemmings Redux replay gate: 160/160 native
  wins, 160/160 recorded rescue-frame matches and all 158 exact-version pairs
  completing. All 160 routes also survive an encoded mid-route playback
  checkpoint and finish in the same full simulation state. The older
  exact-version archive reaches 159/160; its remaining `Manic 32` route sends
  the crowd into water before its recorded Nuke and needs a source-engine result
  before it can be classified as current evidence.
- Capture and compare CE completion frames, final simulation state, destructive
  masks and animated gadget states; the native corpus runner cannot substitute
  for oracle output.
- Compare live terrain pixels with CE captures. The compositor now follows the
  current collision mask, CE's constructive gradients and canonical Stoner
  terrain art; capture-to-capture oracle validation remains open.
- Match remaining Slider edge transitions, multi-entrance ordering, and paired
  gadget state and animation timing. Triggered traps render their primary busy
  cycle; teleporter/receiver pairs enforce their declared busy interval. Basher, Miner, Bomber,
  Stoner, Fencer and Laserer use the exact CE mask geometry without bundling
  its bitmap files.
- Compare the clean real `.nxrp` corpus result and final state with the source
  engine. Native encoded playback recovery now passes all 160 routes.
- Keep native replay import disabled until real replay comparisons pass.
- Verify pack progress and replay identity in the player-facing application;
  repeat the covered save recovery and changed-content rejection with the
  exact-version winning corpus.

## External evidence needed

The reviewed CE 1.2.0 checkout contains levels and styles but no reference
`.nxrp` files. Its bundled graphics have separate use restrictions. Full
closure therefore needs lawfully held level, style and replay corpora that
cover every required mechanic and pack. Record the source URL or owner,
version, commit or archive hash, level identity, replay hash, result and licence
status. Do not commit third-party game data unless redistribution is authorised.
